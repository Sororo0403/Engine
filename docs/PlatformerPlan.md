# 小さな3Dゲームを作れる状態までの作業

ユーザーが指定した完成条件：床と壁がある小さなステージで、主人公が移動・ジャンプでき、カメラが追従し、落下すると復帰するゲームを作れること。

制作完了の条件は、C++のゲーム固有コードやJSONの手編集を追加せず、Editorで物体・コンポーネントを配置・設定し、保存・読み込み・Play／Stopまで行えること。Engine内部の処理だけが完成した段階では完了としない。

以後の自律作業はこの条件に必要な機能だけを対象にする。下記を実装・検証した時点で作業を終了し、無関係なEditor機能の追加は続けない。プッシュは行わない。

- [x] 衝突用ボックスのデータ・ワールド座標変換・シーン保存の基盤（旧形式との互換性を含む）
- [x] 共通Add Componentメニューから衝突形状を追加し、Inspectorで編集・削除・Undo・保存できる（Sceneで形状を表示）
- [x] 床・壁・天井との衝突、重力、移動、ジャンプのEngine処理
- [x] 主人公を追従するカメラ、落下時の開始位置への復帰
- [x] Inspectorで必要な設定を編集でき、Undo／Redoと保存・読み込みに対応
- [x] 編集シーンを保持したPlay／Stopと、ゲーム操作用の入力制御
- [x] 床・壁・主人公を備える小さなサンプルステージ
- [x] Debug・Releaseビルド、衝突・ジャンプ・追従・復帰・再生終了時の編集内容保持を検証

操作はWASDで移動、Spaceでジャンプを基本とする。既存の3Dモデル表示とSceneビューを使い、ゲーム用機能をEngine、制作・再生UIをEditorに置く。

実装時の基準：既存の `Editor/resources/models/box.glb` のローカル範囲は各軸 `[-1, 1]`。サンプルの衝突形状はモデルに合わせて半分の大きさを `(1, 1, 1)` とする。

完成確認：EditorのAdd ComponentとInspectorで設定を作成し、通常のSceneDocumentで保存・再読み込みしたデータをSceneSimulationで再生する統合テストがDebug・Releaseで成功。実際のImGuiイベントによる追加・ドラッグ・カメラ対象選択・削除Undoと、既存の選択・ギズモ・履歴・ファイル操作の回帰テストも成功した。

GPU確認：Debug・Releaseそれぞれで、実際のEditorPlayMode・SceneRendererを使用する非表示診断アプリが100フレームを正常終了。途中のGame描画先リサイズとStop後の再生開始を含む。設定ファイルへの保存は無効化して検証した。

操作手順は `docs/GameplayWorkflow.md`。今回必要な範囲の機能がそろったため、この時点で自律的な機能追加を終了する。現在の対象は入力で操作する主人公1体、追従カメラ1台、静的な床・壁。
